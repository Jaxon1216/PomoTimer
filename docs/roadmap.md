# 分阶段路线图

## 总览

路线图按可验证的能力拆分。每个阶段只在前一阶段的质量门通过后开始；不以“代码已写完”代替真实 macOS/Windows 验证。

| 阶段 | 名称 | 交付重点 | 明确不包含 |
| --- | --- | --- | --- |
| 0 | 工程地基 | Electron/React/Go 架构、受限 IPC、SQLite、测试和 CI | 摄像头、统计 UI、站立模式 |
| 1 | 首个可用版本 | 计时、小挂件、输入监控、两种休息、本地统计 | 摄像头、站立模式、账号/云同步 |
| 2 | 本地摄像头在场检测 | 显式授权、本地人脸存在、自动回退 | 身份识别、强活体反欺骗、姿态分析 |
| 3 | 站立专注与产品硬化 | 手动站立模式、可访问性、签名/更新/诊断 | 未经验证的姿态/运动识别 |

## 阶段 0：工程地基

### 目标

建立可在 macOS 和 Windows 上运行、可测试、可打包的最小工程，并验证 Electron 主进程和 Go Core 的边界。

### 进入条件

- 本文档集和根目录 `AGENTS.md` 已审核。
- 开发环境安装 Go `1.24+`，并可执行 `go version`。
- Node/npm 版本符合 Electron 依赖要求。
- 已确认应用标识、用户数据目录和初始打包命名。

### 实施范围

- 初始化 npm workspace 和 `apps/desktop`：
  - Electron + `electron-vite` + React + TypeScript strict。
  - Main、preload、renderer 分离。
  - `contextIsolation: true`、`nodeIntegration: false`、sandbox、CSP。
- 初始化 `apps/core`：
  - Go sidecar 入口。
  - stdin/stdout JSON-RPC 行协议。
  - `core.initialize`、`timer.getSnapshot` 的最小握手。
  - SQLite 打开和 `schema_migrations` 基础设施。
- 实现 Main 侧车管理：
  - 开发模式与打包模式的可执行文件解析。
  - 生命周期、握手、stderr 诊断、受控重启。
  - 无法连接时的只读错误状态。
- 建立类型与协议校验：
  - TypeScript 运行时 schema。
  - Go JSON 解码、未知字段拒绝、64 KiB 行大小上限。
- 建立测试与 CI 骨架：
  - Vitest、Go `testing`、Playwright Electron。
  - macOS 和 Windows CI job，至少构建、类型检查和单元测试。

### 验收标准

1. 开发模式能启动 Electron、启动 Core 并显示 `core.initialize` 返回的快照。
2. Renderer 只能通过 `window.pomodoro` 读取快照；无法访问 Node、SQLite 或通用 IPC。
3. 损坏的协议行、版本不匹配和 Core 退出会显示可理解错误，不会让 Renderer 伪造计时状态。
4. 首次运行创建应用数据目录和数据库；再次运行可完成迁移握手。
5. macOS 和 Windows CI 都能通过构建与基础测试。

### 发布门槛

- `npm run lint`、`npm run typecheck`、`npm run test`、`go test ./...` 和 `go vet ./...` 全部通过。
- IPC/协议安全评审确认没有暴露通用 `ipcRenderer` 或 Node API。
- 不发布给最终用户，只提供开发构建。

### 回退

阶段 0 失败时可完全停留在文档与最小握手，不引入临时 HTTP 服务、无验证 IPC 或 Renderer 计时备份逻辑。

## 阶段 1：首个可用版本

### 目标

交付一个实际可使用的离线番茄钟：完整默认周期、系统输入闲置监测、两种休息模式、本地统计和可伸缩小挂件。

### 实施范围

#### 计时与设置

- Go 状态机实现 `idle`、`running`、`auto-paused`、`manual-paused`。
- 默认序列：30 分钟专注、5 分钟短休、30 分钟专注、5 分钟短休、30 分钟专注、10 分钟长休。
- 设置专注/短休/长休时长、每周期专注轮数、输入阈值、默认休息模式、主题、通知和常驻顶部。
- 实现开始、暂停、继续、下一步、重置、重启恢复和系统睡眠/恢复。
- 手动暂停锁定自动恢复；自动暂停期间不扣减时间。

#### 输入监测与休息

- Main 每秒读取系统级闲置秒数并发送到 Core。
- macOS 和 Windows 都验证真实键盘、鼠标和触控板活动。
- 专注使用输入在场/离席自动暂停与恢复。
- 活动休息在无输入达到阈值后计时、输入后暂停。
- 桌前休息同样在无输入达到阈值后计时、输入后暂停；它不依赖未来摄像头模式。
- 监测 API 失败时显示降级状态，不基于失败信号暂停。

#### UI 和系统集成

- 小挂件、常规计时器和展开工作台布局。
- 倒计时圆环、当前轮次、检测状态、暂停/继续和下一步。
- 浅色、深色、跟随系统主题；稳定最小/最大窗口约束。
- 托盘菜单、轮次完成/自动暂停通知、常驻顶部。
- 键盘可操作、可见焦点、屏幕阅读器标签与非颜色状态提示。

#### 统计

- `completed_focus_sessions` 持久化。
- 今日、周汇总和最近 52 周 GitHub 风格热力图。
- 仅完整完成的专注轮计入分钟和轮次。

### 验收标准

1. 默认周期按 `30/5/30/5/30/10` 正确生成，并且在设置调整后仅于指定的下一轮/下一周期生效。
2. 无输入满 40 秒会自动暂停专注；输入恢复后自动继续。手动暂停后输入不能自动继续。
3. 两种休息模式都遵循 [产品规格](./product-spec.md) 的规则，下一步/重置不产生虚假的统计。
4. 系统睡眠、锁屏、应用退出/恢复后，计时停在 `auto-paused`，离线时间不计入。
5. 一次完整专注会准确写入本机日期、日/周统计和热力图。
6. 小挂件、主窗口和托盘对同一 Core 快照一致；任意入口执行命令后全部同步。
7. 在真实 macOS 和 Windows 设备上，系统闲置、通知、托盘和 suspend/resume 都通过手工测试。

### 测试矩阵

| 类型 | 最低覆盖 |
| --- | --- |
| Go 单元测试 | 所有状态迁移、周期 1-8 轮、阈值边界、手动锁、信号过期、恢复和统计。 |
| SQLite 测试 | 初始迁移、升级、事务失败、跨日聚合、备份路径。 |
| Electron Main 测试 | idle 采样、托盘命令、侧车重启、电源事件、IPC 校验。 |
| React 测试 | 三种窗口形态、暂停状态、主题、可访问标签、热力图。 |
| E2E | 默认轮次、自动暂停/恢复、两种休息、手动锁、重启恢复、多窗口同步。 |
| 手工 | macOS 与 Windows 的硬件输入、通知、最小窗口尺寸和睡眠/恢复。 |

### 发布门槛

- 阶段 0 的所有检查持续通过。
- 完成一次 macOS 和 Windows 发布候选打包及手工测试记录。
- 没有 P0/P1 计时准确性、自动化锁、数据丢失或平台输入监测缺陷。
- 隐私审查确认没有记录输入内容、活动窗口、鼠标坐标或摄像头数据。

### 回退

- 输入监测不可靠时允许用户关闭自动化并手动计时；不得假装监测正常。
- 有统计迁移问题时保留备份数据库并停用写入，不删除记录。
- 发布后发现严重自动暂停错误时，通过配置开关禁用自动化，保留计时和已完成统计。

## 阶段 2：隐私优先的摄像头在场检测

### 目标

在不改变“完全本地、可回退、无身份识别”原则的前提下，提供可切换的人脸在场检测源。

### 实施范围

- 设置中的清晰同意流程、隐私说明、状态和操作系统授权引导。
- 一个 Renderer 作为唯一 camera owner，通过 `getUserMedia` 请求无音频视频流。
- 打包的本地 MediaPipe WASM 和模型；约 640x480、10-15 FPS 的人脸在场推理。
- 布尔 presence、序号、时间戳协议；无帧、边界框或设备标签跨进程。
- 2 秒离席、1 秒在场的本地防抖。
- 摄像头源与输入源二选一；权限拒绝、设备缺失、流中断、窗口关闭或模型失败时自动回退输入源。
- macOS `NSCameraUsageDescription`、Windows 相机权限和 Electron permission handler 验证。

### 明确不包含

- 人脸识别、脸部特征数据库、年龄/情绪/注意力分析。
- 照片、视频或屏幕回放的严格反欺骗活检。
- 姿态估计、活动量或走动距离推断。
- 云端视觉 API、远程模型下载、上传视频。

### 验收标准

1. 用户未开启摄像头时，应用不请求权限、不点亮摄像头、不加载模型。
2. 用户启用后，视频只在本地内存处理，Go/SQLite/日志只能收到布尔 presence 和必要状态。
3. 摄像头模式下，专注和活动休息依据产品规格正确暂停/继续。
4. 拒绝授权、没有摄像头、拔出设备、关闭 owner 窗口和模型错误都可回退输入检测，且不崩溃或静默计时。
5. macOS 和 Windows 的真实设备上权限流程、状态提示、休眠/恢复和后台窗口行为均通过测试。

### 发布门槛

- 完成隐私复核，确认包内容、网络请求、日志和数据库不包含图像/脸部数据。
- 检测误暂停问题有可重现测试与可见的手动恢复路径。
- 真实 macOS 和 Windows 摄像头测试均通过，且 Phase 1 输入模式没有回归。

### 回退

摄像头能力独立于核心计时。发现严重缺陷时，通过功能开关禁用 camera source，默认输入模式继续可用，已完成统计不受影响。

## 阶段 3：站立专注与产品硬化

### 目标

增加轻量的手动站立专注模式，并把应用提升到可分发的桌面产品质量。

### 实施范围

- 手动启动“站立专注”：当前专注时长取配置专注时长的 50%。
- 已完成统计中增加 `mode: standing` 标签，可在统计视图筛选/展示。
- 站立模式采用舒适度和姿势变化提示，不验证实际站立，不做医疗结论。
- 可访问性审计：键盘导航、屏幕阅读器、对比度、缩放、通知可控性。
- 错误诊断：有界本地日志、侧车崩溃恢复信息、用户可定位但不泄露敏感数据。
- 正式打包：macOS 签名/公证，Windows 代码签名，更新机制与发布流程。

### 验收标准

1. 启动站立模式会生成时长为普通专注设置 50% 的专注轮，暂停/恢复/统计规则与普通专注一致。
2. 用户可分辨和筛选站立/坐姿完成轮，但产品不声称检测到实际姿势。
3. 关键工作流可完全用键盘完成，并满足定义的可访问性检查。
4. 签名构建在 macOS 和 Windows 上可安装、可启动 Core、可创建本地数据库并完成更新前检查。
5. 侧车或数据库故障的诊断不会包含输入、视频或脸部数据。

### 发布门槛

- Phase 1 和 Phase 2 的回归套件均通过。
- 完成 macOS 与 Windows 安装、升级、卸载/重装和数据库保留测试。
- 安全与隐私复核通过；自动更新和签名密钥有受控的发布流程。

### 回退

站立模式是独立预设，可在设置中关闭。签名、更新或诊断问题不得影响离线计时、数据读取或输入监测。

## 未来候选项

以下项目不属于当前承诺，必须经过单独需求确认、设计评审和隐私/测试计划后才排期：

- 自定义多个番茄预设。
- 跨设备同步与账号。
- 自动工作时段和日历集成。
- 可选导出 CSV/JSON。
- 摄像头姿态/动作识别。
- Linux 支持。
