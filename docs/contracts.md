# Electron 与 Go Core 契约

## 1. 范围

本文件定义 Electron Main 与 Go Core 之间的协议，以及由该协议承载的业务模型。协议仅存在于同一台机器的父子进程 stdin/stdout 管道中。

- 编码：UTF-8。
- 分帧：每行一个完整 JSON 对象，行尾为 `\n`。
- 格式：JSON-RPC 2.0。
- 版本：`protocolVersion: 1`。
- 路径：Main 负责启动 Core，Renderer 永远不能访问此协议。
- 传输中禁止包含原始输入、鼠标位置、视频帧、脸部边界框、设备标签或任何身份数据。

## 2. 共享类型

### 2.1 枚举

```ts
type RoundKind = "focus" | "short-break" | "long-break";

type TimerStatus =
  | "idle"
  | "running"
  | "auto-paused"
  | "manual-paused";

type BreakMode = "active" | "desk";
type PresenceSource = "input" | "camera";
type Presence = "present" | "away" | "unknown";

type PauseReason =
  | "none"
  | "input-away"
  | "camera-away"
  | "break-condition"
  | "system-suspend"
  | "core-recovery"
  | "source-unavailable";
```

`completed` 是 Core 内部的瞬时转换状态，只通过 `timer.roundCompleted` 事件表达，不写入稳定的 `TimerSnapshot.status`。

### 2.2 设置

```ts
interface Settings {
  version: 1;
  focusDurationSeconds: number;       // default 1800, range 300..7200
  shortBreakDurationSeconds: number;  // default 300, range 60..3600
  longBreakDurationSeconds: number;   // default 600, range 60..5400
  focusRoundsPerCycle: number;        // default 3, range 1..8
  inputIdleThresholdSeconds: number;  // default 40, range 10..600
  focusPresenceSource: PresenceSource; // default "input"
  defaultBreakMode: BreakMode;         // default "active"
  theme: "light" | "dark" | "system";  // default "system"
  alwaysOnTop: boolean;                // default false
  notificationsEnabled: boolean;       // default true
}

type SettingsPatch = Partial<Omit<Settings, "version">>;
```

`theme`、`alwaysOnTop` 和 `notificationsEnabled` are forwarded to Main after persistence but do not affect Core timing. The Core still stores them so all local preferences have one durable owner.

Settings that alter a round configuration are captured into the newly created round. They do not mutate a current round:

- Duration changes apply when a new round of that kind is generated.
- `focusRoundsPerCycle` applies when the next cycle starts.
- `focusPresenceSource` applies when a new focus round is generated or the user resets the current focus round.
- `defaultBreakMode` applies when a new break round is generated.
- `inputIdleThresholdSeconds` is used by the next input sample.

### 2.3 轮次和快照

```ts
interface Round {
  kind: RoundKind;
  cycleNumber: number;          // one-based
  positionInCycle: number;      // one-based, includes breaks
  focusRoundNumber: number | null;
  breakMode: BreakMode | null;
  totalDurationMs: number;
}

interface AutomationState {
  activePresenceSource: PresenceSource;
  inputPresence: Presence;
  cameraPresence: Presence;
  inputMonitoringAvailable: boolean;
  cameraMonitoringAvailable: boolean;
  manualPauseLocked: boolean;
  pauseReason: PauseReason;
}

interface TimerSnapshot {
  revision: number;             // increases after each state transition
  emittedAt: string;            // RFC 3339 UTC
  round: Round;
  status: TimerStatus;
  remainingMs: number;          // clamped to [0, round.totalDurationMs]
  automation: AutomationState;
}
```

`remainingMs` is calculated by Core when the snapshot is emitted. Renderer may animate locally between ticks, but it must replace local display with every later `revision`.

### 2.4 已完成专注记录与统计

```ts
interface CompletedFocusSession {
  id: string;                   // UUID generated by Core
  completedAt: string;          // RFC 3339 UTC
  localDate: string;            // YYYY-MM-DD in initialize.timeZone
  localOffsetMinutes: number;
  cycleNumber: number;
  focusRoundNumber: number;
  plannedDurationSeconds: number;
  activeDurationSeconds: number;
  mode: "seated" | "standing"; // "standing" is Phase 3 only
}

interface DailyFocusTotal {
  localDate: string;
  completedFocusMinutes: number;
  completedFocusRounds: number;
}

interface StatisticsSnapshot {
  generatedAt: string;
  today: DailyFocusTotal;
  week: DailyFocusTotal[];
  heatmap: DailyFocusTotal[];   // up to the latest 52 local weeks
}
```

Only a fully completed `focus` round produces `CompletedFocusSession`. A skipped, reset, abandoned, auto-paused, manually paused, or recovered-incomplete round produces no record.

## 3. JSON-RPC Envelope

### 3.1 Requests and responses

Main sends requests with a unique, strictly increasing numeric `id`.

```json
{"jsonrpc":"2.0","id":17,"method":"timer.pause","params":{}}
```

Core replies exactly once:

```json
{"jsonrpc":"2.0","id":17,"result":{"snapshot":{"revision":9}}}
```

or:

```json
{
  "jsonrpc":"2.0",
  "id":17,
  "error":{
    "code":-32010,
    "message":"invalid timer transition",
    "data":{"status":"idle","method":"timer.pause"}
  }
}
```

### 3.2 Notifications

Core emits events with no `id`.

```json
{
  "jsonrpc":"2.0",
  "method":"timer.snapshot",
  "params":{"snapshot":{"revision":9}}
}
```

Main may send high-frequency signal notifications without `id`; Core must not reply:

```json
{
  "jsonrpc":"2.0",
  "method":"signal.inputIdle",
  "params":{"sequence":412,"observedAt":"2026-09-07T08:01:02Z","idleSeconds":41}
}
```

Malformed JSON, unknown fields in a strongly typed command, or oversized lines are protocol errors. The maximum line size is 64 KiB.

## 4. Request Methods

### 4.1 `core.initialize`

Called once after each sidecar start.

```ts
interface InitializeParams {
  protocolVersion: 1;
  instanceId: string;            // UUID generated by Main
  dataDirectory: string;         // Electron userData directory
  locale: string;                // e.g. "zh-CN"
  timeZone: string;              // IANA zone, e.g. "Asia/Shanghai"
}

interface InitializeResult {
  protocolVersion: 1;
  capabilities: {
    inputMonitoring: boolean;
    cameraPresence: boolean;     // false until Phase 2
    standingFocus: boolean;      // false until Phase 3
  };
  settings: Settings;
  snapshot: TimerSnapshot;
  statistics: StatisticsSnapshot;
}
```

Core creates/migrates the database before returning. If persisted state says `running`, Core derives the latest persisted remaining time, changes it to `auto-paused` with `pauseReason: "core-recovery"`, persists it, then returns that snapshot.

### 4.2 `timer.getSnapshot`

Returns the authoritative current `TimerSnapshot`. Main uses it after a recoverable protocol or UI synchronization error.

### 4.3 `timer.start`

No parameters.

- Valid from `idle`.
- Valid from a break `auto-paused` state as an explicit manual start.
- Changes status to `running`.
- Clears `manualPauseLocked`.
- Returns the changed snapshot.

It is invalid from `running` or `manual-paused`. `timer.resume` is used for paused states.

### 4.4 `timer.pause`

No parameters.

- Valid only from `running`.
- Changes status to `manual-paused`.
- Sets `manualPauseLocked: true`.
- Freezes `remainingMs`.

### 4.5 `timer.resume`

No parameters.

- Valid from `auto-paused` or `manual-paused`.
- Changes status to `running`.
- Clears `manualPauseLocked`.
- For a focus round, this is an explicit user override and can start even if the most recent presence state is `away`. The next valid signal can auto-pause it again.

### 4.6 `timer.next`

No parameters.

- Valid from any stable timer status.
- Freezes and discards current round without creating a completed-focus record.
- Generates the following round.
- The next focus round is `idle`; the next break round is `auto-paused` with `pauseReason: "break-condition"`.

### 4.7 `timer.reset`

No parameters.

- Valid from any stable timer status.
- Restores the current round's captured `totalDurationMs`.
- Changes status to `idle`.
- Clears the manual pause lock and automatic pause reason.
- Does not change the cycle position and creates no statistics record.

### 4.8 `settings.get`

Returns the current `Settings`.

### 4.9 `settings.update`

```ts
interface SettingsUpdateResult {
  settings: Settings;
  effects: Array<{
    field: keyof SettingsPatch;
    applies: "immediately" | "next-round" | "next-cycle" | "after-reset";
  }>;
}
```

The request is transactional: all fields validate and persist, or none do. Unknown settings keys are rejected.

## 5. Signal and System Notifications

### 5.1 `signal.inputIdle`

```ts
interface InputIdleParams {
  sequence: number;              // monotonically increasing per Main process
  observedAt: string;            // RFC 3339 UTC
  idleSeconds: number;           // integer, 0..86400
}
```

Core accepts a sample only when `sequence` is greater than the last accepted input sequence and `observedAt` is not more than 10 seconds ahead of Core's wall clock. An old or duplicate sample is ignored without changing timer state.

Core maps `idleSeconds >= settings.inputIdleThresholdSeconds` to `away`; otherwise it maps to `present`.

### 5.2 `signal.cameraPresence`

Phase 2 only:

```ts
interface CameraPresenceParams {
  sequence: number;              // monotonically increasing per camera owner
  observedAt: string;            // RFC 3339 UTC
  present: boolean;
}
```

Main accepts this only from the registered camera-owner window and rate-limits it to at most 10 messages per second. Core uses no image data and debounces boolean events:

- 2 consecutive seconds of `present: false` become `cameraPresence: "away"`.
- 1 consecutive second of `present: true` becomes `cameraPresence: "present"`.

When Main detects permission loss, owner-window close, stream end or model failure, it sends:

```json
{
  "jsonrpc":"2.0",
  "method":"signal.sourceAvailability",
  "params":{"source":"camera","available":false}
}
```

Core marks camera unavailable. If camera is the selected focus source, it changes active source to `input`, emits a snapshot, and sets `pauseReason: "source-unavailable"` only if it cannot safely determine a replacement input state.

### 5.3 `signal.sourceAvailability`

```ts
interface SourceAvailabilityParams {
  source: PresenceSource;
  available: boolean;
}
```

Input availability is controlled by Main; camera availability is controlled by the camera owner through Main. A source becoming unavailable does not fabricate an `away` event.

### 5.4 `system.suspend` and `system.resume`

```ts
interface SystemEventParams {
  observedAt: string;
}
```

`system.suspend` transitions a running round to `auto-paused` with `pauseReason: "system-suspend"` and persists it immediately. `system.resume` does not decrement time or directly start a round; subsequent valid monitoring signals or an explicit resume determine the next transition.

## 6. Core Events

### 6.1 `timer.snapshot`

Emitted:

- after initialization;
- after every user command or automatic state transition;
- every second while `running`, for UI precision;
- after an availability or automation-state change that affects UI;
- after recovery.

```ts
interface TimerSnapshotEvent {
  snapshot: TimerSnapshot;
}
```

### 6.2 `timer.roundCompleted`

```ts
interface RoundCompletedEvent {
  completedRound: Round;
  completedFocusSession: CompletedFocusSession | null;
  nextSnapshot: TimerSnapshot;
}
```

For a break, `completedFocusSession` is `null`. For a focus round, Core inserts the record in the same database transaction that persists the next snapshot.

### 6.3 `stats.changed`

```ts
interface StatisticsChangedEvent {
  statistics: StatisticsSnapshot;
}
```

Emitted only after an inserted completed-focus record or a local-date/timezone recalculation that changes aggregates.

### 6.4 `core.error`

```ts
interface CoreErrorEvent {
  code: string;
  message: string;
  recoverable: boolean;
}
```

This event contains no filesystem paths, database contents, user input or camera metadata. Detailed diagnostics stay in bounded local logs controlled by Main.

## 7. Error Codes

| Code | Name | Meaning | Main/Renderer behavior |
| ---: | --- | --- | --- |
| `-32600` | `INVALID_REQUEST` | Invalid JSON-RPC envelope. | Treat as protocol failure when received from Core. |
| `-32601` | `METHOD_NOT_FOUND` | Unsupported method. | Treat as Main/Core version error. |
| `-32602` | `INVALID_PARAMS` | Request field missing, invalid, or unknown. | Display request feedback; do not retry automatically. |
| `-32603` | `INTERNAL_ERROR` | Unexpected Core failure. | Refresh snapshot or restart Core according to supervisor rules. |
| `-32001` | `VERSION_MISMATCH` | `protocolVersion` differs. | Stop startup and request matching application build. |
| `-32002` | `CORE_NOT_INITIALIZED` | Method before successful initialization. | Main sequencing bug; restart Core. |
| `-32010` | `INVALID_TRANSITION` | Command invalid in current status. | Refresh UI from returned/current snapshot. |
| `-32011` | `STALE_SIGNAL` | Old signal was rejected. | No UI error; Main continues sampling. |
| `-32020` | `STORE_UNAVAILABLE` | SQLite unavailable, locked beyond policy, or corrupt. | Disable mutations; offer recovery path. |
| `-32021` | `MIGRATION_FAILED` | Schema migration failed. | Preserve backup and block normal startup. |
| `-32030` | `SOURCE_UNAVAILABLE` | Requested source is unavailable. | Fall back only as documented; show status. |

## 8. SQLite Contract

### 8.1 Schema

The actual migration uses parameterized SQL and explicit schema versioning. The initial logical schema is:

```sql
CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  checksum TEXT NOT NULL,
  applied_at_utc TEXT NOT NULL
);

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value_json TEXT NOT NULL,
  updated_at_utc TEXT NOT NULL
);

CREATE TABLE timer_snapshot (
  singleton INTEGER PRIMARY KEY CHECK (singleton = 1),
  schema_version INTEGER NOT NULL,
  revision INTEGER NOT NULL,
  snapshot_json TEXT NOT NULL,
  checkpointed_at_utc TEXT NOT NULL
);

CREATE TABLE completed_focus_sessions (
  id TEXT PRIMARY KEY,
  completed_at_utc TEXT NOT NULL,
  local_date TEXT NOT NULL,
  local_offset_minutes INTEGER NOT NULL,
  cycle_number INTEGER NOT NULL,
  focus_round_number INTEGER NOT NULL,
  planned_duration_seconds INTEGER NOT NULL,
  active_duration_seconds INTEGER NOT NULL,
  mode TEXT NOT NULL CHECK (mode IN ('seated', 'standing'))
);

CREATE INDEX completed_focus_sessions_local_date_idx
  ON completed_focus_sessions(local_date);
```

No table stores individual input samples, camera samples, camera device identifiers, images, face coordinates, or automatic-pause history.

### 8.2 Snapshot checkpointing

Core persists immediately after:

- start, pause, resume, next, reset;
- automatic pause/resume;
- round completion;
- settings update that affects future rounds;
- system suspend;
- source availability changes.

While running, Core checkpoints a frozen derived `remainingMs` at most every 30 seconds. If the process crashes between checkpoints, the recovered round is auto-paused with the last checkpointed remainder. This can lose up to 30 seconds of recorded progress but never counts time while the app was offline.

### 8.3 Migration and corruption

- Migrations run one version at a time in a transaction.
- The migration checksum prevents silently changing an already released migration.
- Before recovery from a malformed database or failed migration, Core copies the database and WAL/SHM files to a timestamped backup directory.
- Core does not auto-delete user data. A deliberate reinitialize action is required after a recovery failure.

## 9. State and Statistics Algorithms

### 9.1 Timer loop pseudocode

```text
on command or accepted signal or one-second tick:
  lock state
  nowMono = monotonicNow()

  if status == running:
    remaining = max(0, frozenRemainingMs - (nowMono - runningSinceMono))
    if remaining == 0:
      completeRoundTransaction()
      emit roundCompleted, snapshot, and maybe stats.changed
      unlock
      return

  apply command or policy transition

  if a transition enters running:
    runningSinceMono = nowMono
  else if a transition leaves running:
    frozenRemainingMs = derived remaining
    runningSinceMono = unset

  persist if this is a durable transition or checkpoint is due
  increment revision if observable state changed
  emit snapshot if observable state changed or this is a UI tick
  unlock
```

### 9.2 Automation policy pseudocode

```text
desiredPresence =
  if round.kind == "desk break": inputPresence
  else if round uses source "camera": cameraPresence
  else inputPresence

shouldRun =
  if round.kind == "focus": desiredPresence == present
  else desiredPresence == away

if status == manual-paused:
  do nothing
else if round.kind == focus and status == idle:
  do nothing  // focus requires a user start
else if shouldRun and status == auto-paused:
  transition to running
else if not shouldRun and status == running:
  transition to auto-paused with matching pause reason
```

The policy never transitions an `unknown` signal into `away`; unknown means "do not introduce a new automatic pause." A running timer remains in its prior state until a valid signal or a system event arrives.

### 9.3 Completion transaction pseudocode

```text
begin transaction
  derive remaining == 0
  if current round is focus:
    insert completed_focus_session using completion UTC and configured local timezone
  generate next round with settings captured for its kind
  choose next stable status:
    focus -> idle
    break -> auto-paused with break-condition
  persist next timer snapshot
commit transaction
emit roundCompleted
emit snapshot
if focus inserted: emit stats.changed
```

## 10. Renderer Contract

Main maps Core events to typed preload events. Renderer must:

- Subscribe once per mounted root and unsubscribe on unmount.
- Treat `revision` as the ordering key. It ignores a snapshot whose revision is lower than the latest rendered revision.
- Use `remainingMs` as display truth; it may animate only toward the next Core snapshot.
- Disable mutations while Core is unavailable, but keep the last snapshot visible and label it stale.
- Show a status message for `manual-paused`, `auto-paused`, source unavailable, and break-condition waiting.
- Never infer completion or write statistics locally.
