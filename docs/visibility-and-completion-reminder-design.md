# 窗口可见性与完成提醒

日期：2026-11-10。状态：两轮需求均已确认，已实现无声完成卡片；验证结果与仍待复现场景单独记录。

## 已确认目标

- 开启常驻顶部与桌面跟随后，普通应用窗口、macOS 桌面切换和其他应用原生全屏均纳入可见性目标；用户正在使用的应用保留键盘焦点。
- 完成提醒使用独立无声卡片，主窗口隐藏时仍可看到，自动出现不抢键盘焦点。
- 卡片保留到用户点击“知道了”，不自动消失；同一轮不再叠加系统完成通知。

“常驻顶部”和“桌面跟随”保留现有的独立含义，不将置顶等同于参与其他工作空间。相关术语见[领域词汇](../GLOSSARY.md)，既有窗口规则与取舍见[桌面挂件设计](desktop-widget-design.md)。

## 基线与证据边界

本轮以最新 `origin/main` 的 `7e350c3`（beta.3）为基线。最初查阅的原工作区仍停在 `codex/resize-to-widget` 的 `ae00fa7`；其中“未处理桌面和全屏跟随、置顶默认关闭”的事实不能作为最新主线的结论。

最新主线在 macOS 使用 panel 实现桌面和原生全屏跟随，普通置顶使用 floating 层级；新安装的置顶、桌面跟随和自动淡化默认开启，升级保留已有置顶选择。已有本机原生全屏探针证据，但实际应用遮挡、桌面滑动、Split View 和外接屏仍需按具体构建复现；不能仅因窗口标志为置顶就判定实际可见。既有结果见[桌面挂件验证](desktop-widget-validation.md)。

Main 的 `publishSnapshot` 在成功保存自然完成的轮次后，尝试发出系统通知；`notify` 只检查应用开关和平台支持，没有显式静音、用户可见的投递结果或完成弹窗。计时器界面切到下一轮，因此系统通知未呈现时缺少明确的完成反馈。用户本次未感知提醒的根因尚未复现，不能直接归于操作系统权限、开发构建或通知实现缺失。

## 已采用的呈现与生命周期

卡片在计时器所在显示器工作区的右下方出现，采用 340×240 的默认尺寸，并约束在可用工作区内。主窗口已关闭时使用主显示器。显示完成时间、已完成的专注或休息及下一阶段；保持现有主题。

- 专注、短休和长休自然计满并成功保存后各产生一次提醒；跳过、重置和保存失败不产生提醒。下一次自然完成替换尚未关闭的旧卡片，始终只有最新条目，旧卡片的迟到确认无效。
- 点击“知道了”或主动聚焦后按 Escape 关闭；卡片不会自行消失。确认只隐藏并清除该条提醒；窗口复用，以便确认 IPC 正常完成回复。
- 保留原有的自动专注和休息规则，未关闭卡片不阻止下一轮计时，确认不隐含开始、暂停或跳过命令；真实点击仍是系统输入样本的一部分。
- 复用已有 `notificationsEnabled` 偏好，界面改称“完成弹窗与暂停通知”，升级保留选择。关闭开关清除当前卡片；重新打开不补发旧结果。
- 锁屏/睡眠隐藏卡片，恢复后重新显示本次运行中未确认的条目；退出清除，重启不补发历史提醒。剩余的系统睡眠暂停通知显式静音。

提醒不得将“进入下一轮”误写为“下一轮已经开始”；现有触控和监控自动化的规则继续以[产品规格](product-spec.md)为准。

## 实施约束与接续

`CompletionReminders` 由 Main 持有，使用独立 session、页面和自包含 preload；所有媒体及其他权限请求拒绝。其白名单只包含读取、订阅和按 ID 确认当前提醒，不扩大主窗口的 sender 权限。主窗口的创建和显式唤起路径包含焦点与摄像头生命周期操作，因此卡片单独创建，使用 `showInactive()` 显示；macOS 使用与既有桌面跟随相同的 panel 能力和普通悬浮层级。

TimerEngine 仅增加进程内已提交完成元数据，不改变计时迁移或数据库结构；界面失败不进入存储故障冻结路径。两个 preload 分别打包为自包含文件，避免多入口共享分块在 Electron sandbox 的受限 `require` 中加载失败。

置顶异常在本轮的合成普通应用遮挡测试中暂未复现，保留现有普通 floating 层级，不以猜测提高系统层级。新的原生探针使用自己的窗口身份、实际 Window Server 顺序与重叠关系验证，并保留关闭置顶的反例；具体 OS、构建、命令和结果见[验证记录](completion-reminder-validation.md)。
